# أحچيلي (Ahcheely)

منصة أسئلة وأجواب اجتماعية عربية مستوحاة من تجربة ASKfm، بهوية بصرية مستقلة.

الرابط العام: https://wissam-ahcheely.github.io/ahcheely/

## حالة المشروع (تُحدَّث بصدق بعد كل مرحلة)

| المرحلة | المحتوى | الحالة |
|---|---|---|
| 0 | فحص البيئة والمستودع | منجز |
| 1 | الهوية + الحسابات + الملف الشخصي | منجز ومختبر بالكامل |
| 2 | الأسئلة والمجهولية وصندوق الوارد والإجابات | كود مدفوع + إصلاح قواعد حرجة، بانتظار إعادة نشر القواعد ثم إعادة اختبار الإجابة |
| 3 | Feed والمتابعة والإعجابات والبحث والحظر | لم تبدأ |
| 4 | الوسائط عبر Cloudinary | لم تبدأ |
| 5 | الاستطلاعات والتعليقات والمحادثات والإشعارات | لم تبدأ |
| 6 | الإشراف والإدارة | لم تبدأ |
| 7 | العملات (تتطلب دراسة خطة Blaze) | مؤجلة |
| 8 | التدقيق النهائي والإطلاق | — |

## التقنيات
- الواجهة: HTML5 + CSS3 + JavaScript (ES Modules) بلا أي عملية Build، عربية RTL بالكامل، Mobile-First، وضع داكن.
- الخلفية: Firebase Authentication + Cloud Firestore + Security Rules.
- الوسائط: Cloudinary (تُدمج في المرحلة 4).
- النشر: GitHub Pages تلقائياً من فرع main.

## نموذج البيانات (المرحلة 2)
| المجموعة | الحقول الأساسية | الوصول |
|---|---|---|
| users/{uid} | username, displayName, bio, allowAnonQuestions, createdAt | قراءة عامة، تعديل للمالك فقط (بلا username/createdAt) |
| usernames/{name} | uid | حجز الأسماء: إنشاء للمالك فقط، لا تحديث ولا حذف |
| users/{uid}/inbox/{qid} | content, isAnon, fromUid*, fromUsername*, status, readAt, answerId | قراءة/تعديل/حذف للمستلم حصراً؛ الإنشاء مقيّد بالقواعد |
| answers/{aid} | qid, questionText, isAnon, authorUid, authorUsername, text, status | قراءة عامة للمنشور فقط؛ إنشاء للمستلم بعد تحقق كامل؛ لا تحديث؛ حذف للمالك |
| reports/{rid} | type, targetId, reason, byUid | إنشاء فقط (المراجعة في المرحلة 6) |

* الحقلان fromUid/fromUsername غير موجودين إطلاقاً في الأسئلة المجهولة (أقوى مجهولية ممكنة: لا هوية عند أي مستوى، ولا حتى للإدارة).

الحدود الحالية للنصوص: السؤال 5–500 محرفاً، الإجابة حتى 2000 محرف، النبذة 280، البلاغ 500.

## إعداد Firebase (مرة واحدة، من المتصفح فقط)
1. `console.firebase.google.com` ← مشروع `ahcheely`.
2. **Authentication** ← **Get started** ← **Email/Password** ← تفعيل (Toggle).
3. **Firestore Database** ← **Create database** ← وضع Production.
4. **Firestore Database** ← تبويب **Rules** ← حذف الموجود ولصق محتوى `firestore.rules` ← **Publish**.
5. **Project settings** ← **Your apps** ← تطبيق الويب ← نسخ كائن `firebaseConfig` ← يُلصق في `firebase-config.js`.

## خطوتا إعداد إلزاميتان لعمل المرحلة 2 (من Firebase Console فقط)
1. **نشر قواعد المرحلة 2**: Firestore Database ← تبويب **Rules** ← حذف الموجود ← لصق محتوى `firestore.rules` الحالي من المستودع ← زر **Publish**. بدون هذا ستُرفض كل ميزات الأسئلة والإجابات.
2. **إنشاء الفهرس المركب** (مرة واحدة): Firestore Database ← تبويب **Indexes** ← **Add index** ← Collection ID: `answers` ← الحقول بالترتيب: `authorUid` **Ascending**، `status` **Ascending**، `createdAt` **Descending** ← Scope: **Collection** ← **Create**. يجهز خلال دقائق؛ حتى جهوزه ستظهر رسالة خطأ في Console عند فتح الملفات الشخصية مع رابط مباشر لإنشائه بنقرة.

## الأمان
- مفاتيح إعداد Firebase للويب معرّفات عامة وليست أسراراً؛ الأسرار الفعلية (مفاتيح الخدمة، api_secret لـ Cloudinary) لا توضع في هذا المستودع أبداً.
- السؤال قبل الإجابة يُقرأه المستلم فقط (صندوق الوارد)، ولا يظهر في أي مكان عام إطلاقاً.
- السؤال المجهول لا يحمل أي هوية مرسل في أي حقل، والقواعد **ترفض** أي محاولة إنشائه مع هوية.
- الإجابة تُنشأ فقط بعد تحقق القواعد أن السؤال في صندوق المستلم ولم يُجب عنه، وبنص مطابق حرفياً، وبنقل أمين لهوية المرسل. الإجابة تتم في معاملة واحدة (Transaction) فلا نشر جزئي ولا إجابات مزدوجة.
- لا يمكن تعديل الإجابات بعد النشر، ولا تغيير عدادات أو رصيد من العميل، والبلاغات إنشاء فقط.
- تصحيح مهم (2026-10): شرط منع الإجابة المزدوجة كان يقرأ حقلاً غير موجود فيُرفض كل إنشاء إجابة؛ صُحح ليتحقق من وجود الحقل أولاً. وصُحح وسم المقروء الذي كان يُرفض لأن تحديث readAt وحده لا يحمل status. **يجب إعادة نشر firestore.rules في الـ Console بعد أي تعديل عليه.**
- الإجابة تحمل نسخة من نص السؤال، لذا حذف السؤال الوارد لا يكسر الإجابة المنشورة.

## قيود معروفة (خطة Spark المجانية)
- لا تتوفر Cloud Functions ⇒ تُؤجل بصدق: تواقيع الرفع الموقعة، أتمتة الإشراف الخادمية، إشعارات Push الخادمية، والعمليات المالية الخادمية.
- مضاد السبام/التكرار الحالي من جانب العميل فقط (مهلة 10 ثوان + منع تكرار دقيقتين)؛ الحد الخادمي الحقيقي يتطلب Cloud Functions.
- مراجعة البلاغات بشرية وتُنفذ في المرحلة 6 (الإبلاغ يعمل الآن كإنشاء بلاغ فقط).
